`planRefresh` decides a note is still Atlas's to replace by comparing
`digestOf(body)` against the digest stored on the note — where `body` is
whatever the markdown layer hands back. Any change that normalises a body on
write (reflowing, re-escaping, trimming a trailing newline) flips **every**
source-produced note to "yours" at once.

The coupling itself is fine; ADR-0003 keeps it honest. What makes this a card is
that nothing fails loudly if that promise breaks. The promise lives in an ADR and
in the adapter, the rule that depends on it lives in the domain, and no test
crosses the seam. The failure is silent and permanent: no error, the feed's text
simply stops landing in those notes forever, and the panel's counts move from
"refreshed" to "kept your text" where nobody is looking.

Scope it as a regression guard, not a redesign: take a source-produced note, run
it through the real parse/serialize round trip with no edit, assert the digest
still matches, and name ADR-0003 in the comment as the thing it protects. Then
the day someone changes serialization, that test goes red with the reason
attached.

Deliberately **not** carding the alternative designs. Digesting the record's
text instead of the note's body breaks the "did you edit this?" question the
digest exists to answer, and storing the last-written body verbatim doubles what
every note carries.
