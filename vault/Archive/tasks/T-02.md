Playwright's `getByText` is a case-insensitive substring match by default, and the save indicator reads `Unsaved` / `Saving…` / `Saved`. So `getByText('Saved')` matches **"Unsaved"**, and every `expect(…getByText('Saved')).toBeVisible()` passes on a note that never saved.

There are 19 of them across 10 specs (`grep -n "getByText('Saved')" e2e/*.ts`), including the core save tests in `editing.spec.ts` and `unsaved-edits.spec.ts`. Some of those tests also check the file on disk and are covered that way; any that lean on the indicator alone have been asserting nothing.

The same class caused a flake in `dashboard.spec.ts`: `getByLabel('Dashboard')` substring-matches the sidebar's **Dashboards** region too, and whether both exist at the moment of the check depends on load — strict-mode violation, intermittently.

Fix with `exact: true` (or a role query), **and prove each one can now fail** — making a fixed assertion falsifiable may reveal a test whose save genuinely never happened, which would be a real bug rather than a test bug. Then sweep `e2e/` for other substring matches that can collide (`getByText`, `getByLabel`, `getByRole({ name })` without `exact`).

Found by the R13-11 agent, which used `exact: true` in its own spec and flagged the rest.
