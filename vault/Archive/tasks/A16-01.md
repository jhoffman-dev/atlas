Failing tests in commit a6198b6.

1. **High, data loss.** "Add a property" judges "taken" by the rows on screen; `title` (hidden when it heads the page) and `type` (never shown) are not there, so adding either writes `''` over it. Use the note's real frontmatter keys; reserve `type`/`atlas`.
2. **Medium.** Donut: options folded into "Other" come back as 0-count rows; a real option named "Other" clashes with the gathered tail.
3. **Medium.** Board chips: the index returns checkboxes as text `'false'`, so an unticked box shows as a ticked chip.
4. **Medium.** Filter values that look numeric (`101`, `007`, `1.10`) never match a text property — the value type must come from the column's kind.
5. **Low-medium.** Changing the day of a date-time drops its time.
6. **Low.** Dashboard `span`/`width`/`limit` accept arrays and booleans via `Number()`.

## Fixed

1. `newPropertyKey` (domain) now takes every frontmatter key, reserves `type`/`atlas`, and says why it refuses; `useNoteProperties` hands the file's keys to `NotePane` → `PropertiesPanel`.
2. `gatherTail` names the tail apart from real groups and declared options ("Other (N more)"); `withEmptyOptions` skips options that were counted before gathering.
3. `cardChip` reads a checkbox's text: `false`, `0` and blank are unticked.
4. `filterValueFrom` reads digits as a number only for a declared number property; the Filter popover passes the column's kind.
5. `withDatePart` swaps the day and keeps the time; `formatPropertyDate` shows the time, and names the right weekday for years 0–99.
6. `span`, `width` and `limit` accept only a number or its text.
   Also: `withoutValue` picks "a"/"an" by sound ("a unit", "an hour").
