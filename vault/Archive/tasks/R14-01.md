When the vault changes, open panes unmount and run their save-on-leave. That save goes through `fs` **after the host has already moved to the new vault**, so it can write — or strand work — against the wrong vault. A note `notes.md` open in vault A, switch to vault B, and the unsaved text of A's note can land in B's `notes.md`, or be kept as stranded work for B.

This is data loss into a file the person was not editing. The save on the way out must be bound to the vault it was opened in, or must happen before the host switches.

Found by the R13-11 agent while building the per-vault stranded-edit store; out of that card's scope.
