Search palette, capture palette, new-note menu, editor suggestion popup — onto the chosen library's dialog/popover/menu primitives.

Each currently hand-rolls focus trapping, focus restoration, escape, scroll locking, click-outside versus focus-outside, portals and ARIA. That is the layer that is subtly wrong for years, and it is the reason this phase exists.

Keep every class name and every existing test. The look must not change: this is a behaviour swap, and if the diff shows visual churn something has gone wrong.

Three of the four moved: the search palette and the capture palette onto
`Dialog`, the new-note menu onto `Menu`. The editor's suggestion popup stays
hand-rolled — it is anchored to a caret rather than a trigger, focus has to stay
in the editor, and TipTap's suggestion plugin already owns what is open and what
is selected. The reasoning is in a comment above the component.

What the library fixed: focus never came back to what opened an overlay, Tab
walked out of the palettes into the sidebar, the menu answered no key at all —
not Escape, not an arrow — and nothing behind an open overlay was hidden from
assistive technology. Each of those is now asserted, in WebKit where they can be
judged.
