The design brief said "User space is the vault minus what the other sections
already show — `.atlas` stops appearing as a folder; it is the other four
sections." That sentence is wrong, and the sidebar implements it faithfully.

`.atlas` is not only views and dashboards. It also holds the type definitions,
the templates, the sources and `settings.md`. In this vault that is ten notes
with nowhere to be clicked:

    types/{task,person,company,event}.md
    templates/{Task,Person,Company,Daily,Dashboard}.md
    sources/Milestones.md

Starring one still works — a favourite can be any note, including one the index
never sees, which is how `e2e/sources.spec.ts` now reaches its source note — but
a note you have to know about in order to find is not findable.

Three ways out, in rough order of preference:

1. **A Sources section** for `.atlas/sources`, plus types and templates reached
   from where they are already used — a type row could offer "edit this type",
   and the `+` menu already lists the templates.
2. **A Settings route** holding everything in `.atlas` that is configuration
   rather than content.
3. **List the leftovers** under User space as an `.atlas` folder again, which is
   honest but undoes the thing the section split was for.

Whichever is chosen, fix the sentence in `vault/docs/design/look-and-feel.md`
too, or the next person reads the same wrong rule.
