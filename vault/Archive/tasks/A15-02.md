Found by the adversarial pass on P15-02; failing tests in commit 1667a65 (`packages/application/src/api/api.adversarial.test.ts`, `packages/domain/src/vault/new-note.test.ts`).

1. **High.** `/v1/sql` runs `ATTACH DATABASE '/any/file.db'` and `VACUUM INTO '/anywhere'` on the "read-only" index connection: any token holder can read any SQLite file the app can reach and create files outside the vault. The cached connection keeps an ATTACH for later requests. Fix in the host (`index.rs` `run_query`): refuse non-readonly statements (`sqlite3_stmt_readonly`), and deny ATTACH/DETACH (attached-db limit 0 or an authorizer). Also protects the app's own SQL editor.
2. **High.** Append / body replace / create-with-body on a note whose frontmatter closes on the file's last byte glues the body onto `---`; the frontmatter never closes and every property is lost.
3. **Medium.** Daily and capture answer 500 when the name is taken between listing and creating, and capture always 500s on a case-insensitive clash (`call sam` vs `Call Sam.md`).
4. **Medium.** `noteFileName(". .env")` gives `.env` — capture (and the UI's New note / quick capture) can create a hidden note.
5. **Low.** Appending `---\ntype: X\n---` to an empty note turns it into frontmatter.

Also noted (no test yet): create read-back after a vault switch; unnamed create answers `exists` on a case clash; `.atlas` rows appear in `/v1/query` and view runs; `query_failed` passes host error text through verbatim (may include absolute paths); search can return fewer hits than `limit`.
