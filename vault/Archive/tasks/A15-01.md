Found by the adversarial pass on P15-03; failing tests in `apps/desktop/src-tauri/src/api/adversarial_tests.rs` (commit 354ef21).

1. **Medium.** A client that stops reading holds a connection forever, token or not, and connections are uncapped — any local process can exhaust the app's file descriptors, and then vault saves fail. Deadline per connection, cap concurrent connections.
2. **Medium.** A turn-on whose file save fails leaves the server listening with the live token while Settings says off. The reverse (failed turn-off) leaves the file saying on.
3. **Low-medium.** A valid `api.json` at 0644 is loaded and kept at 0644.
4. **Low.** `GET http://evil.test/v1/...` with a good Host is served; the request-line authority is ignored.
5. **Low.** `?q=%FF` is rewritten to U+FFFD instead of refused.

Design risk, same pass: when Atlas is closed, `api.json` still names the port and token; another local process can listen there and collect the token from the MCP server. At minimum rotate the token when the recorded port turns out to be taken, and clients must connect to `127.0.0.1` literally, never `localhost`.

Resolved: connections capped at 32 (excess wait in the accept queue) with a 60 s lifetime then 60 s drain; turn-on/turn-off all-or-nothing against the file save; a loose `api.json` is made 0600 and its token replaced; absolute-form targets refused 403; non-UTF-8 query refused 400; a taken recorded port replaces the token before serving; no main window answers 500 at once instead of waiting 30 s.
