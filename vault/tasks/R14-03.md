`usePanes` loads the remembered layout asynchronously, so for one render after a vault switch the panes still hold the old vault's paths under the new vault. R14-01 found a race in exactly that frame — work taken back by a read and never kept again — and fixed the symptom by checking the latest render. Loading the layout per vault synchronously would remove the frame, and every future race that lives in it.

Done: `usePanes` reads the remembered layout (and starts a fresh history) in the render that sees the new vault, not in an effect after it, so no render holds one vault's paths under another's key, including the very first render.
