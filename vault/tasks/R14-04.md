R14-01 made the host refuse a write aimed at a vault that is no longer open — but `vault` is optional on the write calls, so a caller that does not go through `inVault` is not checked. Every current caller is bound in `app.tsx`. Making it required would force the next caller to decide, rather than trust it to remember.

Done: the Rust write commands take `vault: String`, and `root_for_write` refuses a write that names none. In TS the host's port is `HostVaultFsPort` (vault required); the bound `VaultFsPort` takes none and will not accept the host in its place, so `inVault` or `noVaultOpen` is the only way to one. Needs a Rust rebuild (restart `pnpm tauri:dev`).
