A14-06 found a timeline bar that shrank at the end of time: `addDays` could not
write 10000-01-01, so it quietly returned the end date unchanged while the start
moved. `bar-drag.ts` now refuses the move — but only there. Any other caller that
shifts two dates together can hit the same thing, because the failure is silent.

Make it loud: return a result the caller has to handle (or `null`), so the next
caller cannot forget. While there, the separate `asStrings` in
`packages/domain/src/query/frontmatter-query.ts` still keeps repeated view
columns, the way property options did before A14-05.

Done: `addDays` returns null when it cannot move a date (unreadable, or past 9999-12-31 / before 0000-01-01). Every caller decides: a bar or an event stays put, a calendar range and the agenda stop at the last day, a late note ends with its own day, paging stays where it is. `nextOccurrence` had the same bug (it wrote `+010000-01`) and now returns null. `asStrings` drops a repeated view column.
