James, 2026-09-28: "We need to add a log now. I don't want it to be overly verbose but I do need a way of seeing things like automation runs, and if errors come up."

**Decided (can be changed):**

- **What's logged:** one line per event a person would care about:
  - automation runs, dry runs and undos (a summary line; the rule's own log keeps the detail)
  - source refreshes (ok / failed)
  - errors and warnings: any notice shown in red, failed saves, refused writes, index failures, a Claude turn that failed
  - writes made through the local API or MCP (route and note)
  - Claude edits accepted, and undone
  - index rebuilds

  Never keystrokes, routine autosaves, or note contents. Never secrets or absolute machine paths (reuse `messageWithoutPaths`).

- **Levels:** info / warning / error.
- **Storage:** per vault, on this Mac, in the app's data folder, not in the vault (git and sync noise). Append-only JSON lines, bounded to about 30 days or 5 MB, oldest dropped first.
- **UI:** an **Activity** page (sidebar quick row near Automations, or System — Phase 16 look) with:
  - filters: errors only, warnings and up, and each kind
  - text search
  - newest first, with time, level, kind and one line
  - a click-through to the note, rule or source involved
  - a small badge when errors arrive since it was last opened
- **Architecture:** a domain event model and bound rules; an application `ActivityLog` port that every existing use-case reports to (no rules in Rust — it only appends and reads bytes it is handed); the desktop adapter writes the file. Keep it cheap: batched appends, no blocking on the UI.

**Built (2026-09-28):** an Activity page under Automations in the sidebar, with a red badge for errors that arrived since it was last open. Lines: automation runs, dry runs and undos (a run that left notes alone is a warning); source refreshes; API/MCP writes (route and note, with refusals as warnings); Claude Accept/Undo and failed turns; index rebuilds and failures; failed or refused vault writes; and every red notice. The same line again within a minute is dropped. Kept per vault in the app's data folder (`activity/<vault digest>.jsonl`) for 30 days or up to 5 MB (cut back to 4 MB), oldest dropped first.

**For the API/MCP keeper:** the log cannot be read through the API or MCP yet. Writes through them are recorded, but no route reads the log. A `GET /v1/activity` route plus an MCP tool is the follow-up if tools should see it.
