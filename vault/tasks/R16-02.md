The page head shows the title; a note whose body opens with `# <same text>` (every ADR, every new note — new notes are created as `# Untitled`) shows it again as the first line of the body.

A CSS-only hide was built and removed (R16-01): byte-safe, but the caret can still move into the hidden heading (clicking a new note, ArrowUp from the first line), so text could be typed where nobody sees it. Options, needing James's call:

1. **Leave it** — two titles, honest and safe.
2. **The page head _is_ the heading** — edit the first `# heading` in place as the title (Obsidian-style); the body starts after it. Byte-safe, but the heading and a `title:` property must then agree on which wins.
3. **New notes stop writing `# Untitled`** and the title lives in the filename or a `title:` property; existing notes keep their heading (option 1 for them).

Related: search and the index list a note by its heading (R16-01 item 3) while the page head uses the `title` property or the filename, so for an ADR the list and the page disagree until this is settled.

**Resolved by option 3 (U-09, James's decision, 2026-09-24).** New notes, typed notes, board cards, daily notes and API-created notes start empty, and the Task/Project/Person/Company templates no longer end in an empty `#`: the name lives in the filename or a `title` property and is shown once, at the top of the page. Existing notes keep their heading (option 1 for them). Lists no longer prefer the heading either: one title rule everywhere (`pageTitle` — the `title` property, else the filename), so an ADR with no `title` property is listed by its filename, as its page head shows it. Index schema bumped to 4 so caches rebuild with the new titles.
