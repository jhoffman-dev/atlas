Failing tests on branch `worktree-agent-a219f4c5f950d44a6` (commit 3d3c11f); review findings from the code-reviewer pass.

**High / medium:**

- **Stale relations (1):** relations don't re-resolve for `.md` / non-ASCII / NFD targets. Fold names in TS, not SQLite `lower()`.
- **Stale relations (2):** deleting a note in the app leaves relations pointing at it.
- **API:** the API can't run a query view, and runs dashboard query widgets without the vault's types or note paths.
- **Saving a blank query** turns the view into something else (refuse it).
- **A property called `not`** can't be used with IS EMPTY / CONTAINS / STARTS WITH.

**Low:**

- **Dates:** sorting ignores the time of day; a date with a UTC offset is compared by its UTC day.
- **Grouping:** groups sort by label text rather than by value or the query's sort; "unticked" splits between missing and `false`.
- **Editor preview:** the dashboard editor preview resolves links differently.
- **Saving:** it rewrites an unchanged `layout:` line (the frontmatter writer touches unchanged keys).
- **Values:** tags reached through a relation lose their order; a 1000-term OR chain fails in SQLite; two builder values print text that can't be read back.
- **Minor:**
  - text mode runs a query on every keystroke (debounce about 200 ms)
  - build one wiki-link resolver per refresh and per run
  - the sort subquery is evaluated twice
  - `groupRows` is O(n²)
  - dashboard group headings get no note names
  - ADR-0019 vs code on which keys Save writes
