The A21-01 adversarial pass fuzzed editor documents through the writer and back. About 200 fail against the editor model on main (d85534c), before A21-01 — e.g. `**k<&]]&k**` in a table cell loses its bold. Plus:

- **Escapes and entities:** `&amp;` / `&copy;` come back as `&` / `©` on edit, and a leading space in a paragraph saves as `&#x20;`. So does bold ending in a space before a link (`**See&#x20;**[[Name]]`).
- **Wikilinks:** `\[\[x]]` is read as a wikilink and saved as `[[x]]`.
- **CRLF files:** an edited block ends up with mixed line endings.
- **Images:** a link or image wrapped over two lines inside a quote/callout nests a quote on edit (A21-01 fixes the link case; the image case predates it).

**Approach:**

1. Add the seeded property test (editor document → writer → parser → editor document, adjacent text merged).
2. Bucket the failures by cause.
3. Fix at the writer, or keep such blocks as raw source.

Nothing may change a user's content on an unrelated edit (ADR-0003/0004).

- From A22-01: inline `[[_draft_]]` (emphasis characters in a wiki-link target) still reads as italic — needs a wiki-link syntax extension so the target is one token.
