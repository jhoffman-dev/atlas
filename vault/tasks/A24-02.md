Failing tests on branch `worktree-agent-ac040606e8d8bff41` (commit 75f36fa) over the keeper's branch `worktree-agent-a7136bc8ca798c609`; minor review findings from the code-reviewer pass.

**High:**

- **Relation hops leak hidden notes.** A hop (`project.secret`, also in WHERE and GROUP BY labels) reads notes in hidden folders or `.atlas`. The compiled hop only joins targets in user space, and `readNamedNotes` titles are filtered the same way. This is a domain rule, so the app obeys it too.
- **Query views and dashboard query widgets list hidden-folder notes.** Filter them as `/v1/atlas-query` does, preferably in the compiled SQL.

**Medium:**

- **Vault switches go unnoticed.** A mid-run vault switch in the views route and in dashboards isn't detected; add `assertStillOpen`.
- **Widget errors show absolute paths.** Failed dashboard widgets carry absolute paths.
- **`messageWithoutPaths` stops at the first space**, which leaks paths like iCloud's "Mobile Documents".

**Low:**

- **Short pages.** A page comes back short when hidden rows sort first. Fixed by filtering in SQL, not after.
- **`no_vault` masked.** An index failure after a switch answers `query_failed` instead of `no_vault`.
- **Wrong `truncated`.** A query view cut short by its own LIMIT says `truncated: false`.
- **From the review:**
  - `truncated` counts dropped rows
  - move the shared helpers out of the route module
  - throw on a missing group row index
  - the text cap counts UTF-16 units, not characters

Also: check whether the host indexes hidden folders (`.trash`) at all (ADR-0014 skip list). If it does, decide whether it should.
