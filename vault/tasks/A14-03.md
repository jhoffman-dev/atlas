1. Shift+Cmd+N then Cmd+K: nothing visible happens (capture wins the ternary), but `searching` is left true, so closing capture pops the search palette open unasked.
2. New-note menu open, then Cmd+K: the palette opens but `[role=menu]` stays in the DOM — two modal overlays, two focus traps, and Escape returns focus into the menu. Note `getByRole('menu')` counts 0 there (the dialog hides it from the accessibility tree), which is why the test uses a CSS locator.
3. Focus lands on `<body>` when the element that opened the palette was deleted before it closed.

Opening an overlay should close any other. Tests: `e2e/overlay-interleave.spec.ts` (3 failing).
