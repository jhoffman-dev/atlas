James, 2026-09-28: "I would like to have a way to sync between computers the notes, settings and everything, I am thinking that github could be a good way to sync between."

**Decided (can be changed):**

- **Git in the vault folder:** sync is git in the vault folder, run through the Mac's own `git`, authenticated by the GitHub login already on the Mac (the `gh` credential helper or SSH). Atlas never stores a GitHub token. Rust only runs `git` with fixed argument shapes it is handed and reports the result; the TypeScript side decides everything (ADR-0005), like the Claude Code runner (ADR-0021).
- **Setup (Settings → Sync):**
  - On the first Mac, create a **private** GitHub repository for this vault (via `gh repo create --private`), or connect an existing one by URL; then the first commit and push.
  - On another Mac, "Open a vault from GitHub" clones it and opens it.
- **What syncs:** everything in the vault — notes, attachments, `.atlas` (types, views, dashboards, templates, sources, automations and their logs, `settings.md`) and `Chats/`.
- **What never syncs:**
  - secrets (Keychain; set per Mac, per ADR-0017)
  - `.atlas-cache/` (the index rebuilds itself)
  - the Activity log and per-Mac window state

  A managed `.gitignore` is written for these.

- **When it syncs:**
  - it pulls on open
  - then, every few minutes and after typing stops, it commits, pulls and pushes
  - it syncs once more before quitting
  - there's a **Sync now** button
  - each sync, and any failure, goes in the Activity log
- **Conflicts never damage a note:**
  - When both Macs changed a file, this Mac's version stays in place, and the other Mac's version is saved beside it as `<name> (conflict from <Mac>).md`, with a warning. No git conflict markers ever appear in a note.
  - Merges are ordinary merges; there's no rebase or history rewriting.
- **Open notes:** notes with unsaved typing are saved (or waited on) before a commit. A pull that changes an open note reloads it the way an outside edit does today.
- **Automations run on one Mac only**, set in the Sync settings (default: the Mac that set up sync), so two Macs don't both run the same rule.
- **The Atlas code repo is off-limits:** refuse to sync a vault that sits inside another git repository's work tree (e.g. the Atlas code repo), with a clear message.

**James, 2026-09-28 — his own vault:** move his personal notes out of the Atlas code repo's `vault/` into a new `~/Atlas Vault` with its own private GitHub repo, once sync is built. Show him the file list first, keep the originals until he confirms, leave the project's board/docs/ADRs in the code repo, then point Atlas at the new folder.

**James, 2026-09-28 — go further:** "Add in the settings the ability to choose the repo. After that auto commit and push as I am using it. It should also frequently check for changes and pull them."

- **Choose the repository in Settings → Sync:** a picker listing James's own GitHub repositories (via the Mac's `gh` login — `gh repo list` as a fixed, read-only host shape), with search, plus "create a new private repository" and "paste an address". Picking one connects the vault after the host's confirmation dialog; it checks out the repo's default branch (no main/master split).
- **Auto commit and push while working:** about 30 s after typing stops (and after any other change: accepted Claude edits, automations, moves), commit and push; at most every 5 minutes of continuous editing, so a long session is never left unpushed.
- **Frequent pulls:** fetch every minute (cheap when nothing changed) and merge when the remote moved; open notes reload like an outside edit, and unsaved typing is never overwritten.
- **Settings:** both intervals adjustable; a pause switch; the sidebar light shows synced / syncing / behind / error.
