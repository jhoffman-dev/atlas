Failing tests on branch `worktree-agent-af44fdbd0f9c50130` (commit 589edab); review findings from the code-reviewer pass.

**Decided:**

- **Create is never what Enter picks by default.** When "Create …" is the only item, nothing is highlighted: Enter makes a new line and closes the list. Create needs ↓ then Enter, or a click. It is offered only for names of up to 3 words that don't start with `@`.
- **Making a person never changes what an existing `[[link]]` opens.** New people go in a `People/` folder, created if needed. If a note of that name already exists anywhere, the new person is linked by its full path, and the existing links' targets are checked unchanged (test). If that can't be guaranteed, creating is refused with the reason.
- **New person names can't contain `#`, `[`, `]`, `|` or `^`.** Obsidian can't link to them either. Existing people with such names are offered with a link written by path, or left out with a reason.
- **A pending create uses a placeholder at the `@` spot.** Text typed meanwhile goes after it. If the note is re-read from disk or the user undoes, the link is not inserted; the person note is still made and a notice says so.
- **Built-in types are protected by file name _or_ `name:`.** `type:` matching stays exact, as the index does it; the "Mentioned in" check matches that.
- **Unicode and triggers:** NFC/NFD folded in ranking and in `resolveWikiLinkTarget`. Dotted names (`J.R. Hartley`) work. `@` triggers after a non-breaking space and after opening quotes.
