Failing tests on branch `worktree-agent-a984327b934174b51` (commit a8f669a, over the integration branch `worktree-agent-aff36437bdc2d1f38`); review findings from the code-reviewer pass.

**Decided:** unarchive restores to the archived path minus `Archive/` (numbered if taken). `archivedFrom` is used only when it names that same place, so an edited stamp can never move a note elsewhere, rename it, make folders, give it a non-`.md` name, or bury it past the walk's depth. The API never saves someone's unsaved typing: a note (or a linking note) with unsaved typing is left alone and listed in `failed` as `unsaved_in_app`. ADR-0016 gains an amendment naming the one move route and its limits.

**Fix:** per-note link-rewrite failures reported in `failed`; a vault switch mid-batch reports the moves already made; `moves` answer the disk's folder spelling; pruned folder names (node_modules…) matched case-insensitively for every API note path; archiving refused past the walk's depth; a note's own stamped keys come back byte-for-byte (keep their source text, including empty values); removing the last key keeps trailing comments and a blank-line-only block; no trimming of restore paths; a long Archive search is capped rather than overflowing SQLite parameters; malformed YAML on unarchive reported; `api/views.ts` coverage to 90%.
