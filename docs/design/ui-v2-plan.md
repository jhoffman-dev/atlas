## 1. Summary of the design

### Tokens (from `design/target/Tokens.dc.html`, the brief §3, and the `tokens(theme)` blocks of each board)

**Neutrals** (light / dark): `bg #F6F6F7/#111113` (left sidebar, tab strip, board column wells), `surface #FFFFFF/#18181B` (content, cards, right sidebar), `well #F8F8F9/#1D1D21` (table group rows, notice bars), `ink #18181B/#EDEDEF`, `ink-2 #52525B/#B4B4BC`, `ink-3 #6B6B73/#8E8E98` (metadata; measures 5.2:1 on white, 5.4:1 on dark surface, so WCAG AA holds), `line #E6E6E9/#2A2A2F`, `line-soft #ECECEF/#2A2A2F` (row dividers), `hover #F4F4F6/#222227`, `selected #E8E8EB/#26262B`, `focus #6B7BC4/#8F9BE0` (focus ring and editing-cell ring only). The boards also use a `line2`/separator grey for the `·` between metadata (`#C4C4CA` light, `#4A4A52` dark), a disabled-control ink `#C4C4CA`, a chart grid `#F1F1F3/#232328` and bar grey `#D4D4D8/#3F3F46`; these need tokens too.

**Status** (dot / text / tint, light): Inbox `#9DB4C8/#3D5A70/#EAF0F5`, Backlog `#A1A1AA/#52525B/#F1F1F3`, Next `#7EA2DD/#2D4F8A/#E8EFFB`, Doing `#DDA54E/#7A5312/#FBF1DF`, Waiting `#C9A0B8/#6E3F5C/#F6ECF2`, Review `#A595E3/#4E3F8F/#EFEBFB`, Done `#7DBF93/#2F6B45/#E6F3EA`. Dark: same dot (Backlog dot becomes `#7C7C86`), tint = dot at 14–16% alpha (`Table.dc.html` gives `rgba(161,161,170,0.14)`, `rgba(165,149,227,0.16)`, `rgba(125,191,147,0.16)`), text lightened (`#C4C4CC`, `#CBC1F2`, `#A9D9B8`). Status must always carry its label; never colour alone.

**Buttons** (28px, radius 6, 12.5/500): Primary `#E3ECFB/#23457E` (dark `rgba(126,162,221,.18)/#B5CBF0`), Positive `#E3F2E8/#26603D` border `#C8E3D2`, Destructive `#FBEDED/#9A3F3F` border `#F2D4D4`, Secondary `#FFFFFF/#18181B` border `#D9D9DE`, Ghost transparent/`#52525B`. Dark values for Positive/Destructive/Secondary are unspecified: proposed by the brief's own rule (dot at ~15% alpha, lightened text): Positive `rgba(125,191,147,.16)/#A9D9B8/rgba(125,191,147,.35)`, Destructive `rgba(226,120,120,.16)/#F0A8A8/rgba(226,120,120,.35)`, Secondary `#1D1D21/#EDEDEF/#3A3A40` (open question 17).

**Type**: system stack `-apple-system, BlinkMacSystemFont, 'SF Pro Text', 'Segoe UI', system-ui` replacing bundled Manrope (`@fontsource-variable/manrope` in `apps/desktop/package.json`, imported in `apps/desktop/src/main.tsx`). Weights 400/500/600 only, tabular figures. Scale: note title 24/600 −0.01em; section title 15/600; card title, active tab, emphasis 13/500; body/rows/nav 13/400; column and group label 12.5/600; metadata 12/400 ink-3; section and column headers 11.5/500 ink-3; mono 12 `ui-monospace`; inline code 12.5 mono on `#F4F4F6`, radius 4.

**Spacing and shape**: scale 4 8 12 16 20 24. Radius: chips/pills 4, buttons/inputs 6, popovers/menus/peek/toast 8, board columns and cards 0, fully round only dots and avatars. Shadows only on popovers/menus/peek/toast (`0 8px 24px #0000000F`; peek `0 0 0 1px rgba(0,0,0,.06), 0 24px 64px rgba(0,0,0,.22)`; toast on a dark `#18181B` surface). Borders 1px `line`. Sizes: left sidebar 224, right sidebar 300–340, tab strip 36, nav bar 40 (the Flow boards) or 44 (Main/Table header), view bar 44, table header and group row 32, table row 34, control and sidebar item 28, board column gap 8, board card padding 8/10.

**Density**: everything edge to edge on `surface`; no floating rounded panel, no hero tile, no subtitle block; one bold thing per row (the title); metadata on one line joined by `·`; empty values and zero counts hidden; never the word "Empty".

### Layout shell (`Sidebar.dc.html`, `FlowTable.dc.html`, `FlowSplit.dc.html`)

Left sidebar (224, `bg`, 1px right hairline): vault switcher row (20px ink tile with the initial, 13/600 name, chevron, + and hide buttons), then fixed rows at 28px (Search with `⌘K` as its right-hand hint, Today, Inbox with count, Weekly review, Graph, Tags, Automations, Activity, Templates, Terms), then sections Dashboards, Favorites (hint "Star a note to keep it here"), Views, Types (with counts); active row gets `selected` bg, 500 weight, ink icon; counts ink-3 tabular, hidden at 0; footer Settings + sync cloud + theme moon button above a top hairline. The mockup has no Pages tree (open question 20).

Each pane, top to bottom: tab strip (36px, `bg`, 188px square tabs with icon, label, × on the active tab, + button; the active tab is `surface` with a 2px top border, ink in the focused pane and `#D4D4D8` in the unfocused one), nav bar (40px: ← →, breadcrumb "Views / Task table" with a 12px ink-3 count, then the view's actions, Saved, ☆, ⋯ and the right-sidebar toggle), content. `Main.dc.html`/`Table.dc.html` draw a 44px breadcrumb bar and a 44px view bar with underline view tabs (Board, All tasks, Inbox, Today, Calendar, Roadmap) and Filter/Sort/Group/New task; the Flow boards draw tab strip + nav bar and no view bar. These disagree (open question 1); the plan assumes tab strip + nav bar always, and the 44px view bar only on a typed view.

Right sidebar (300–340, `surface`, 1px left hairline): a 36px tab row on `bg` (Properties, Backlinks, Outline, ×), a title block, 30px property rows, "4 empty properties", a Summary block, and Open / New tab buttons at the foot; or the type editor (`FlowType.dc.html`). Collapses first when the window narrows, then the left.

### Key components and pages

- **Table** (`Table.dc.html`, `FlowTable.dc.html`): grid header 32px 12/500 ink-3 without icons, sticky; group rows 32px on `well` with chevron, dot, 12.5/600 label, count; rows 34px; status as a 20px tinted pill (6px dot, 12/500); numbers tabular; empty cells blank; "Show N more" row; 30px footer with totals and "Grouped by status · sorted by phase"; a 28px checkbox column; the editing cell has a 1.5px inset `focus` ring; a status picker popover (220px, radius 8, filter field, rows with dot, label, tick, number key).
- **Board** (`Main.dc.html`): equal-width square columns on `well` with a 34px head (8px bare dot, 12.5/600 label, 12 ink-3 count, + button), white square cards with 1px line, title 13/500 two-line clamp, one-line 12 ink-3 summary, metadata line `P14 · Bug fixer · 1h`, done cards with ink-2 title and a sage check, "N more" and "No tasks".
- **Dashboard** (`Dashboard.dc.html`): 84px strip of six headline numbers (11.5/500 label, 24/600 value, 12 ink-3 sub) divided by hairlines; a 340px row with "Tasks per phase" (grey bars, current phase `#7EA2DD`, labels only on the tallest and current, hover title, table toggle) and "By status" (10px stacked bar, then a Status/Tasks/Share table); a three-column row of hairline panels: Largest phases (bar rank), Waiting for review, Backlog.
- **Peek** (`FlowPeek.dc.html`): 840px modal dialog over a 30% ink scrim, 44px header (↑ ↓, "3 of 186 in Task table", Saved, expand, new tab, split, ⋯, ×), 24/600 title, one-line properties strip with "+ 4 empty", hairline, 14px/1.6 body, 34px key-hint footer. Link preview card: 360px, radius 8, title + "Task · Phase 16", four lines, footer hints.
- **Inbox** (`FlowInbox.dc.html`): 40px notice bar on `well` (Preview / Not now), "To clarify" section with 40px rows and N/W/S/T/P/D one-key actions shown on the focused row, Proposals section with filters (All, High confidence, Needs a choice), "Accept all high confidence", dense rows (checkbox, KIND, title + explanation, confidence pill, Reject/Edit/Accept) and "pick one" radio groups.
- **Type editor** (`FlowType.dc.html`): in the right sidebar at 340px: icon tile, 15/600 name, mono path, properties list with grip/kind/chevron, an open property's name field, kind select and three checkboxes, Add property, Template and Default view rows, a "Saved · edits apply to every Meeting note" foot.

## 3. Ordered slices

Conventions for every slice: one PR, opened as a draft, mergeable on its own against `main`; screenshots are `pnpm design:refs && pnpm shots && pnpm design:compare` at 1440×900 in both themes, plus the gallery page (`apps/desktop/gallery.html`) where a slice adds primitives; tests are component (vitest + Testing Library, behaviour assertions, never snapshots) and e2e (Playwright/WebKit); structural slices run `pnpm perf:budgets` locally and must not raise any count in `tools/perf/budgets.json` (and must not edit that file; only the perf track lowers it). Each behaviour slice spawns the guide keeper (`docs/guide/index.html`) and, where the API contract changes, the API/MCP keeper. No real names anywhere; mockup data already uses the e2e vault's fictional ones.

### Slice 0 — Design pipeline on v2 (S)

- **Goal**: `pnpm design:refs` renders `design/v2`, `pnpm design:compare` pairs each app surface with its v2 board, `design/README.md`'s table is updated, and the tool no longer needs Google Fonts (the v2 boards use the system stack).
- **Files**: `tools/design/refs.ts` (TARGET → `design/target` after a `git mv design/v2/* design/target/`, or a `DESIGN_DIR` constant; drop the Manrope check), `tools/design/compare.ts` (SURFACES: dashboard→Dashboard, board→Main, all-tasks→Table, sidebar→Sidebar, tokens→Tokens, and placeholders table-editing→FlowTable, peek→FlowPeek, split→FlowSplit, type-editor→FlowType, inbox→FlowInbox), `tools/design/dc-render.ts` + `dc-render.test.ts` only if the v2 `hint-placeholder-count`/`hint-placeholder-val="{{true}}"` attributes produce empty-hole warnings, `design/README.md`, `design/v2` → `design/target` move (open question 14).
- **Dependencies**: none. **Parallel**: with anything. **Risks**: none to the app.
- **Tests**: `dc-render.test.ts` cases for the hint attributes; a smoke that every board renders with zero missing holes. **Screenshots**: the 13 v2 renders in `design/out/refs`.
